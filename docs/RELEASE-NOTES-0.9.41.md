# v0.9.41 · 写回前核「行身份」：不再往数据区外的空行写

> 2026-10-29 · 触发：爹地报「放单方式汇总_20261028」面板显示范围 第 1–127 行、识别 97 个提单号，
> 真实数据只到 114 行，结果 K115 / K116 出现了「查询超时…」「失败：MSC 查无此号…」
> —— 写到数据区以外的空行去了。

## 根因：只有「文档身份」校验，没有「行身份」校验

`row` 是扫描那一刻的 `r1+i`。从查询到写回之间（实时写几秒、暂存补写几十分钟），
一旦删行/插行/排序，这个行号就指向别的行 —— 甚至指向根本没有单号的空行。
上次修的是「**表**变了要拦」（`docKey()`），这次是「**行**变了没拦」。

放大器：扫描范围取的是整表 `UsedRange`。结果列 K 在 115/116 行被写进过文字后，
UsedRange 末行被顶到那里 → 下次仍扫 127 行 → 又写一次。
**错误结果自己把范围撑大，然后证明自己没错。**

## 改法

1. **写前身份校验（唯一一把尺）** `verifyRowIdentity(sheet, row, number, numCol)`：
   写之前读 `numberCol@row`，与查询时那个单号比对，不等或为空 → 不写。
   - 单号列该行为空 → 直接 false（**空行硬保护**不用另写一条规则，同一个判断覆盖）
   - 归一化后比对（全角转半角、去空白/连字符、大写）：用户手打的号常带空格全角，
     严格比对会把「同一行」误判成错位而**少写**，那是另一种错
   - 同格两号（订舱号/提单号）命中任一即可
2. **唯一写入口** `writeRowChecked()`：写结果、补写暂存、写船期（ETD/ETA）全部走它或先过 `verifyRowIdentity`，
   不许再直接调 `writeCell` —— 否则下次又会只修一处。
3. **暂存队列同一把尺**：`_flushPending` 每条都核；对不上的直接弃写（留着只会每 2.5 秒重试一次都过不去），
   计入「错位跳过」。
4. **暂存去重 key 带上身份**：`${doc}|${number}|${numCol}|${outCol}|${row}`。
   原来只按 `${row}|${outCol}`，删行后两条结果落到同一个 row 时，后进的把前一条**静默去重掉**（直接丢一条，无提示）。
   去掉 row 又会把「同号两行（一票两箱 / 复制重复行）」静默合并 —— 去重是为了幂等，不是为了省存储。
5. **扫描范围按单号列收口**：末行 = 单号列最后一个非空行（读不全就退回 UsedRange）。
   结果列下面的脏文字再也不会把范围顶大；清掉脏文字后范围自动缩回 114。
   合并单元格：纵向合并只有左上角有值，末行落在最后一个有值的锚点，锚点下面是同一票（本来也没单号可查），不漏数据。
6. **界面**：横幅「表格行变了（删/插/排序），本轮 N 行结果对不上，已跳过不写 —— 点③重跑」，
   同时「上次刷新」时间旁标「这个时间与范围行数不可信」。新一轮刷新开始时归零，不挂僵尸提示。

## 红-绿（`scripts/state-probe.mjs`）

判据不看读回值，只看**写动作落在哪一格**：每条写入的 row，删行之后该行单号列必须还是它的单号。
桩里新增 `window.__deleteRow(n)`（下方整体上移、末行清掉、UsedRange 跟着缩）——只改行号不改 grid 是假场景。

| 用例 | 0.9.40（红） | 0.9.41（绿） |
|---|---|---|
| H22 查询跑到一半删掉第 3 行 | 写 6 格、**5 格错位**，其中「第 7 行单号列是空的，却写了…」 | 写 1 格、冲突 0、横幅报「本轮 5 行结果对不上」 |
| H23 范围内有空行 + 跑到一半被清空的行 | 「空行被写=[3]」 | 空行被写=[]，正常行照写 [2,5,6] |

H23 带反向断言（正常行必须真写到 ≥2 格），防止「一律不写」也能过。
