# v0.9.42 · 写回收敛成唯一入口 + 批量读写（治卡顿，从结构上消灭错位）

> 2026-10-29 · 触发：爹地报「97 行一轮，WPS 明显卡」，同时 0.9.41 才刚把「写错行」堵上。
> 这一版不是再打一个补丁，而是把写回做成**一个口子 + 一次批量**：结构上让「写到错位行」没有入口。

## 病根（读码 + 实测）

- `writeCell` 有 4 种降级写法，**每格写完还要读回校验** → 每格至少 2 次同步 COM 调用打在主线程；
  97 行 = 200+ 次，再加上里程碑着色（每行一次 `Interior`）、读 POL/POD（每行两次 `readOne`）、
  船司列（每行两遍）—— 一轮下来 1000+ 次同步调用。桩里给每次调用注入 2ms 忙等后实测：**1072 次**。
- 写回路径散在 4 条：实时写 `writeResult`、暂存补写 `_flushPending`、船期 ETD/ETA、自动重查。
  每条路都得自己记得核一次行身份 —— 只要有一条忘了，0.9.41 那个 bug 就换个入口再犯一次。

## 改法

### 1. 唯一入口 `writeRowChecked(sheet, row, outCol, text, number)`

核行身份 + 写入 + 写后校验三步都在这一层收口，业务代码只能调它。已接入的写回路径：

| # | 路径 | 入口 |
|---|---|---|
| ① | 实时写回 `writeResult`（③ 立即刷新 / 自动刷新 / 手工兜底 `applyManual`） | `writeRowChecked` |
| ② | 暂存补写 `_flushPending`（查询中切走攒下的结果，切回原表补齐） | `writeRowChecked` |
| ③ | 船期回填 `writeScheduleDates`（ETD / ETA 两列，原来直接 `rng.Value2 = ...`） | `writeRowChecked` |
| ④ | 自动重查 `runRetry` → `queryAndWrite` → `writeResult` | `writeRowChecked` |

`grep -n "writeCell(" src/components/TaskPane.vue` 现在只剩 **2 行**：

```
955:    writeCell(sheet, r, c, text) {                        ← 定义（兼容层，4 种降级写法）
1221:      const r = this.writeCell(sheet, w.row, w.col, this._cellValueOf(w))   ← _writeOneChecked（批量写的唯一逐格旁路）
```

也就是说：单行段、批量写失效时的逐格定位，全都收在一个 `_writeOneChecked` 里；
业务路径（实时 / 暂存 / 船期 / 自动重查）的调用点全部清零，要绕开身份校验已经没有入口可绕。

### 2. 批量写：入队 → 按列聚合成连续区段 → 一次 `Range(...).Value2 = [[...]]`

- 每条结果先入队（攒批窗口 400ms，或队列够 10 行立刻落盘），**不是**来一条写一格。
- 落盘时按 (输出列, 单号列) 分组、按行号排序、**切成连续区段**：`Range("K2:K9").Value2 = [[a],[b],...]`。
- 写后**一次批量读回**校验（1 次 COM 校验整段，不是每格一次）。
- **只有批量写失败**（老版本不认二维数组 / 抛错 / 读回不一致）才退回逐格定位；逐格时**依旧逐格核身份**。

实现口径（卡上要求写清）：**只对连续区段批量写，跳过洞**。
批量写会把整段每一格都覆盖，「不写的格」若被覆盖，它的公式/用户手写内容会被替换成死值 ——
这是最隐蔽的一种数据损坏，所以宁可按段写，也不整段覆盖后回填原值。

### 3. 批量读

- 单号列：一轮一次 `Range` 读（0.9.41 已是批量，这次确认逐格读的退路只在批量读失败时才走）。
- 输出列：本轮开头整段一次读 → 「保留旧值」判断、自动刷新「只补空行」都查这份快照，不再每行 `readOne`。
- 船司 / POL / POD / 订舱号列：每列一次读成快照，行内查询查内存。
  **核行身份永远读实时值**（快照只用于分类，绝不能用于身份判断 —— 否则删行后被顶下来的行会「看起来对得上」）。

### 4. 里程碑着色单独一遍批量刷

- 连续行 + 同一种颜色 → 一次 `Range("A2:M9").Interior.Color`（区段批量失败才逐行）。
- 清色改成「账本制」：`ourColor` 记着我们刷过哪一行什么色，只清自己刷过的；
  不再为「这色是不是我们的」每行读一次 `Interior.Color`。用户手工标的底色照样不碰。

## 验收（都是跑出来的数，不是估计）

### 性能（`scripts/write-bench.mjs`，97 行 × 1 列结果，桩里每次表格 API 访问注入 2ms 忙等 ≈ 真实同步 COM 开销）

| 指标 | 0.9.41（改造前） | 0.9.42（改造后） | 变化 |
|---|---|---|---|
| 写回阶段耗时 | **1754 ms** | **351 ms** | **-80%（≈ 1/5）** |
| 一轮同步 COM 调用 | 1072 次 | 184 次 | -83% |
| 批量写次数 / 最大段长 | 0 / — | 24 次 / 4 行 | 全部走批量 |
| 97 格结果是否都落表 | 97 | 97 | 一致 |

> 改造前的数字取自 HEAD 上**只加计时器、不改逻辑**的一份临时构建（同一把尺、同一份桩），
> 不是为了对比而造的模型。复现：`node scripts/write-bench.mjs --build <构建目录> --label <说明>`。

### 正确性（`scripts/state-probe.mjs`，27/27 通过）

- H22 / H23 仍全绿（删行、空行、跑到一半被清空的行：一格不写错位行）。
- **新增 H24**：批量写路径下删中间一行 —— 前一批 4 行已批量落地、后一批里删除点上方的 3 行照写，
  被顶下来的行一格不写（`批量写 2 次、最大段长 4、写入 7 格、删除点及以下被写=[]、冲突 0`）。
  这条与 H22 的区别：H22 只有 1 格合法写入，根本走不到批量写，拦不住「批量段漏了身份校验」。

### 结构

`grep -n "writeCell(" src/components/TaskPane.vue` → 只剩 2 行：定义 + `_writeOneChecked`（批量写的唯一逐格旁路）。

## 同批带上的小改：清掉 OOCL「暂未接入 / 需滑块验证」的旧文案

> 2026-10-29 · 触发：OOCL 追踪**已接入并真单实测**（`engine/tracking/oocl.mjs`，移动版匿名 JSF 页，512ms），
> 但插件侧还留着按「OOCL 根本没接入」写的分支，会给出一句已经不成立的误导文案。

- 删掉 `formatLatest` 里的 OOCL 特判（`carrier === 'oocl'` → 「OOCL 暂未接入（官网需滑块验证）」），
  `no tracking module / not wired up for` 统一走 `「<船司> 未接入追踪（请手工查）」`。
- `knownNotLive` 兜底分支同步改成同一句（原来写「官网需滑块/验证码」，对任何船司都是瞎猜），
  展示名改由 `carrierLabel()` 取：插件短名表 → 桥给的 `name` → id（没适配器的船司也能显示成人名）。
- 新增「站方限流」归类：`限流 / throttled / too many requests / 访问过于频繁` →
  「OOCL 站方限流（过几分钟再查，别连续重试）」，不再被截成半句「失败：OOCL 站方限流（QF8：访问过于…」。
- 失败态兜底链接**实测有线**（本机桥 `GET /track?number=OOLU0000000001&carrier=oocl`）：
  `ok:false · errorKind=throttled · manualUrl=https://pbservice.moc.oocl.com/.../mobile_ct_search.jsf?...`，面板的「手工查」按钮点得开。
- 夹具不再谎报 `oocl: live=false`（桥现在报 12/12 已接入）；未接入分支改用真·无适配器的 **SITC** 演练，
  并新增 **H8b** 反向断言：S/L 写 OOCL 时必须真的发 `/track?carrier=oocl` 且写回一行结果，旧文案一个字都不许出现。
  灵敏度验过：把夹具改回 `oocl: live=false`，H8b 立即变红（26/27）。
- 验收：`grep -rc "暂未接入（官网需滑块验证" dist/ wps-addon-build/` → **0**；
  `verify-all.sh --fast` 10 项全绿。

> 顺带一个运维事实：桥是长驻进程、`identify.mjs` 是启动时载入的 ——
> 引擎侧改了 `manualUrl`（PC 版 → 移动版）之后**必须 `scripts/bridge.sh restart`**，
> 否则 `/carriers` 还会把 PC 版 `cargotracking.aspx` 吐给插件（本次实测踩到，重启后已是移动版）。
